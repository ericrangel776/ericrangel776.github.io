Real-Time Weather Forecast App

A responsive weather lookup app in plain JavaScript: no framework, just a clean fetch layer and honest error states.

JavaScript HTML/CSS Bootstrap 5 REST API
CASE_STUDY.TXT

Overview

A small, focused app: type a city, get current conditions and an outlook, styled cleanly with Bootstrap 5. No build tooling, no framework. The point was to keep the fetch/render loop simple and legible end to end.

The Problem

Public weather APIs are reliable but not infallible: city names are ambiguous, requests can fail, and rate limits exist. A "happy path only" demo is easy to build and unpleasant to actually use the first time a lookup fails silently.

Architecture & Approach

A single fetch layer wraps the API call, normalizes the response into a small internal shape the render functions understand, and surfaces failures as visible UI states rather than console errors:

async function getForecast(city) { try { const res = await fetch(`${API_BASE}?q=${encodeURIComponent(city)}&units=imperial`); if (!res.ok) throw new Error(`Lookup failed (${res.status})`); return await res.json(); } catch (err) { showError("Couldn't find that city. Check the spelling and try again."); return null; } }

Rendering is a pure function of the normalized data: given the same forecast object, it produces the same DOM output every time, which made it straightforward to test by hand against mocked API responses without touching the network.

Results

The app handles the three states that actually matter in practice (loading, success, and a specific, actionable error message) instead of just the success case, which is where most weather-app tutorials stop.

What I'd Do Differently

  • Cache recent lookups in localStorage to avoid refetching the same city repeatedly within a short window.
  • Add geolocation-based lookup as a default, with manual city search as the fallback rather than the only option.
